## Shared contracts (the lead provides them; code against these APIs)

- **Pager** (`ui.pager`, `web/js/ui/pager.js`, lands within about 20 minutes): `ui.pager({ id, total, size, page, noun, onChange({ size, page }) })` returns the footer HTML (`Showing 1–10 of 19 patients`, a "Rows per page" select with **10, 25, 50, 100**, previous and next). `ui.pager.slice(rows, { size, page })` returns the rows for the page; `ui.pager.fromQuery(params)` reads `size` and `page`. Every table you build shows the pager at the **bottom of the page** and **no "N of M" count at the top** (the filter bar's count text is being removed). Persist `size` and `page` in the query with `ui.query.writeQuery`. Do not build your own paging or "Show more".
- **Top bar** (shell, lands within about 20 minutes): every platform page gets a slim bar at the top right with an **FLO** button (sparkle icon) and a **bell**. They dispatch `window.dispatchEvent(new CustomEvent('psyflo:topbar', { detail: { id: 'flo' | 'bell', opener } }))`. The FLO fork listens for `flo`, the Authorizations fork listens for `bell`; each opens a `ui.drawer`. `window.psyfloTopbar.setBadge(id, n)` sets the number on the bell. The page header carries **no date, no time and no "N of M" text** any more.
- Tables: keep `ui.queueTable` and `ui.filterBar` (their look is changing under you; use them as they are).

## Rules for working in the shared tree

- Other forks and the lead edit the same working tree. Use **Edit with exact hunks** on any file you do not own; never rewrite a whole file you do not own; never `git add`, `commit`, `push`, `stash` or `checkout` (the lead commits).
- Files you own are in your own brief. Everything else (notably `web/js/shared/nav.js`, `permissions.js`, `registry.js`, `redirects-live.js`, `maturity.js`, `server/psyflo/project.js`, `authz.js`, `web/css/*`, `web/js/ui/*`, `web/js/app.js`) belongs to the lead: if you need a change there, make the smallest Edit hunk **and say so in your report**, or ask. New routes need the lead; avoid them (deep sections via query params).
- New store actions go in your own `server/psyflo/actions/x-<name>.js` (autoloaded) with a capability entry in `server/psyflo/authz.js` (one hunk) and a projection entry in `server/psyflo/project.js` (one hunk). Every action writes an audit event.
- The hosted build must keep working (`node scripts/build-hosted.mjs`): no `eval`, no downloads (`<a download>`), no network except what the build allows. Screens are discovered automatically from `web/screens/*.dc.html` and `web/js/screens/*.js`.

Add a test suite for what is new. Never weaken an assertion to get green; if a behaviour is dropped on purpose, say so in your report.
