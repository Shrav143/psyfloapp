## Product rules (from the prompt and the reviews; none bend)

1. A person presses Process Form, Get Signature and Send. Psyflo drafts and records; it never signs, never stores credentials, never submits unattended. "Processed", "Signed" and "Synced" states are set only from an observed bridge event or a person's recorded action, never by a simulated writer.
2. Processed or finalized records are write-once. No addendum or late-entry feature. Scan & Enhance Mode B (historical) is read-only and reads Psyflo's captured copies; Mode A (current draft) may fill the open form.
3. Nothing invented. Every statement in a draft traces to a stored record; counts are computed from stored records; missing evidence prints "Evidence missing — verify …". Seeded canned drafts carry the chip "Illustrative sample".
4. Rules (deadlines, units, signature modes) come from the rules table with a source category and a verification label: Officially verified · Payer-specific · Harvest-reported · Unverified demo assumption. Never state a rule as law that is not officially verified.
5. Say "page bridge to the open Lauris page". Never "Lauris API" or "integration".
6. Least privilege, server-side: use `can()` from `web/js/shared/permissions.js`. Admin has no clinical-record access by default.
7. Analytics data carries provenance: `case_backed`, `harvest_export` (labelled "Sample data, illustrative"), `illustrative` (the v3 cohort, ids `COH-…`). One dataset per view, never summed together, minimum group size 5, no patient-level drill-down outside case-backed data plus the clinical-records permission.
8. Maturity chips: Working (unmarked), Simulated, Pilot (preview), Future; use `web/js/shared/maturity.js` and `ui.maturity()`; a feature's level is registered once. Rule provenance chips are a separate axis.
9. Synthetic data only. "Demo data · nothing is real" stays on every app screen. Master ids are canonical (`R-xxxx`, `REF-xxx`, initials); never import v3 Harvest numbers.
10. Interactive means real: every visible control navigates, changes state, opens a useful detail, performs a permitted operation, or says why it is unavailable. No dead buttons, no lorem.

## Foundation notes (F1)

Server track of the foundation. Exact names other engineers rely on. Everything here is demo-grade identity (no identity provider), enforced on the server.

**Sessions and authority**
- `POST /api/session {staffId, presenter?, pin?}` | `{portalToken}` | `{portalClient, presenter:true}` | `{schoolUser, presenter:true}` | `{signOut:true}` returns `{token, actor}`. The token travels in `X-Psyflo-Session` (the `psyflo_session` cookie serves `/files` and `/seed/scripts`). `GET /api/roster` is public (names and roles only). `GET /api/state` needs a session (401) and returns the role projection (`server/psyflo/project.js`): every key is present, withheld data is empty.
- Client (`web/js/api.js`): `api.signIn(staffId,{presenter})`, `api.signInPortal(token)`, `api.signInAs({portalClient|schoolUser})`, `api.signOut()`, `api.session()` (the actor), `api.roster()`, `api.token`. The old shell keeps working: `localStorage.psyflo_user` and portal URLs sign in lazily. The Lauris panel (an iframe) keeps its own session in `sessionStorage` and signs in as the Lauris user on the open page.
- The actor is the session: `this.who()` / `this.actor` inside an action. **Ignore `args.by`, `staff`, `signer`, `who`.** Env: `DEMO_PRESENTER=0` turns presenter mode off, `PRESENTER_PIN`, `DEMO_TIME=HH:MM` fixes the time of day, `DEMO_TEST=1` seeds the random generators and exposes `GET <lauris>/__test/lauris`.
- **Every action needs a capability entry** (`server/psyflo/authz.js`, fail closed: no entry = 403). In your action file: `export const authz = { 'x.thing': { any: ['cap'], scope: (s,args,actor)=>({clientId:args.client}), check: (s,args,actor)=>{...} } }` or `store.defineAction(name, fn, entry)`. Entry kinds: `{any:[caps]}`, `{portalToken:true}` (token in args), `{bridge:true}` (page bridge, validated by attestation), `{internal:true}` (callable only from another action). Declare a projection for a new state key with `export const projection = { key: { clinician:true, supervisor:fn, default:false } }`; an undeclared key reaches clinicians only.
- Refusals: `import { refuse, Refusal, needDocRef, needUnits } from '../gates.js'`. A refusal rolls the whole action back, writes an audit event `Refused · …` and answers 409/422. `store.run` rolls back on any exception.

**Clock and rules**
- `store.clock = {date, time, now(), advance({days, calendar})}` and `web/js/shared/clock.js` (`today(s)`, `now(s)`). Presets start at 3:30 pm Oct 29; a day advance starts the next school day at 9:00 and skips weekends unless `calendar:true`; the advance moves the mock Lauris too (`store.hooks.advance`). No code may read the machine clock or write a story date.
- `web/js/shared/rules.js`: `rule(s,key,scope?)` -> `{value, unit, category, verification, source, verified_on, note, default, enabled}`, `unitsFor(s,service,minutes)`, `unitBands`, `deadline(s,key,from,{unit})` -> `{date, source, verification}`, `decisionDay(s,sent,today,payer)`, `signatureMode(s,doc)`. Table: `seed/extra/rules.json`, edited only by `settings.rule {key,value|reset,reason}` (admin.settings, audited, forward only). Chips: `VERIFICATION[category]`.

**Requests**
- Stages add `needs_approval` ("Pending clinical approval") between `draft_ready` and `awaiting_signature`. `request.processed`, `request.signed`, `request.portalConfirmed`, `note.processed`, `request.set`, `lauris.event` are internal. Flow: Process Form (observed) -> `needs_approval` -> `request.approve {id}` (approve.sra) -> Get Signature observed (signer read from Lauris) -> `signed` -> `request.send {id}` (send.packet) -> `submitted`. `request.resend {id, reason}`, `request.appealSend {id}`, `request.overdueNotice`, `request.infoSend` run the send stub and record its reference; events carry `actor_kind` and `sim:true`.
- Payer decisions need `doc_ref` and are write-once (`recordDecision`; a correction needs `reason`). An approved decision calls `applyAward` (Psyflo's tracker: `client.authorization`, history, and a human task in `state.lauris_tasks`); Psyflo never writes units into Lauris; the task closes when a bridge observation shows the units.
