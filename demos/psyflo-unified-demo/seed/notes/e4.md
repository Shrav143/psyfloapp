## 42 · Analytics (`Analytics.dc.html`)

HOW THE DATA GETS IN · counted from what people did in this demo; three datasets, one per view, never summed.

Captured: the pilot scorecard and Payer Performance are counted from stored requests, processed notes and audit events, so a figure moves when a note is processed in Lauris (the page bridge reports Process Form), a request is sent, or a payer decision is recorded with its document. Patient Outcomes and Patient Population are counted from client records, goals, note content and drafts; the server computes those aggregates for each role and sends only groups of 5 or more (an administrator or a site supervisor never receives diagnoses, goals or note text, and no initials are in what they receive). The seeded baseline (analytics_baseline, payers, compliance) is labelled "Sample data, illustrative": Harvest has not computed it. The illustrative cohort is 120 generated patients (COH-001 to COH-120, no initials, fixed seed) built in the browser; it is not stored and not reconciled with Authorizations.

Flows: stored records -> pure selectors (shared by the server and the browser) -> panels -> screen, CSV and PDF. The six pilot measures are defined once, with numerator, denominator, source and limits, behind the "?" in the scorecard. A group under the minimum (rule analytics.min_group_size, never below 5) prints "Fewer than 5". Patient-level rows exist only for case-backed data and only for a clinician (own caseload). Export writes the period, the filters, the definitions and the dataset into the file, and prints the same cells as the screen. The question box is rule-based (Simulated): it answers only from the figures on the screen and states a limitation otherwise.

Engineering: state.analytics_agg is a derived key, never stored. Maturity: the pilot scorecard is Working; Patient Outcomes, Payer Performance, Patient Population and Export are Future; the question box is Simulated.
