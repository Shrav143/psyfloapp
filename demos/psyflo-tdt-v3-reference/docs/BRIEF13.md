## Shared contracts (HIST13 implements; everyone else codes against them)
### `PSY.api` — the in-browser demo backend (`src/screens/07-api.js`, HIST13)
The user asked for "backend code … to show that these buttons actually do work". Build a small request/response service inside the demo (no network): handlers validate input, read and write `PSY.state` (so results persist for the session and other pages see them), simulate latency, and log every call.
- `PSY.api.route(method, pattern, handler)`; pattern like `'/cases/:case/history'`; `handler({ params, query, body }) → data` (sync or async); throw `PSY.api.error(status, message)` for 400/404/409.
- `PSY.api.get(path)`, `PSY.api.post(path, body)`, `PSY.api.patch(path, body)` → `Promise<data>`; rejects with `{ status, message }`. `PSY.api.latency = [min,max]` ms (default [150,450]; tests set `PSY.api.latency = [0,0]`).
- `PSY.api.log()` → newest first `[{ id, at, method, path, status, ms, summary }]` (kept in `PSY.state.api.log`, max 200). A **Presenter menu item "Demo backend · API log"** opens a modal listing the calls (method, path, status, time, summary) and the route table — so a presenter can show that clicks hit real handlers. Label it "In-browser demo backend (simulated; no external systems)".
- Routes HIST13 provides: `GET /cases/:case/history?scope=auth|denial`, `POST /cases/:case/history`, `POST /voice-calls` `{ case, purpose, scope }`, `GET /voice-calls/:id`, `GET /payers` (the five MCOs). EXT13 adds `GET /roster`, `GET /roster/:laurisId`, `POST /roster/:laurisId/actions/:key/done` (or similar). AUTH13 / DI13 may add routes they need.
### `PSY.hist` — History (`src/screens/08-history.js`, HIST13)
- Event: `{ id, case, scope: 'auth'|'denial', ts: 'YYYY-MM-DDTHH:MM', actor: { kind, name }, action, detail?, ref?, pop?: { kind: 'call'|'doc'|'letter'|'submission'|'note'|'analysis', id } }`.
- Actor kinds and right-hand tags (one small chip per row, distinct colours, each with a short legend tooltip):
  `voice` **Voice agent** (Psyflo's phone agent) · `agent` **Psyflo agent** (automated work: portal submission, status check, document pull) · `psyflo` **Psyflo AI** (drafts, analysis, recommendations — always clinician-reviewed) · `staff` **Staff · <name>** (a person: J. Perez, LPC; M. Wood; K. Hale) · `lauris` **From Lauris** (read from the EHR: signed forms, sessions, authorization records) · `payer` **Payer** (letters, decisions, portal messages from the MCO).
- Backdated seed history for **every case**: the authorization steps (referral, Admission Screening, CNA, ISP in Lauris; Initial SRA drafted by Psyflo AI; clinician review and signature in Lauris by staff; submission by the Psyflo agent through the payer's channel in `PSY.data.payers`; payer receipt; a **voice agent status call** after submission with a reference number; decision letter; units recorded; concurrent SRA preparation when due) and, for denial/partial/info cases, the denial steps (decision received, Psyflo AI analysis, missing evidence, documentation requested from staff, **voice agent follow-up call** to the payer asking for the reference number, what the reviewer needs, whether a peer-to-peer can be scheduled — without inventing payer rules or new deadlines), appeal or reconsideration drafted, staff edits/approval. Dates must agree with what the demo already shows (decision dates, submission dates, deadlines, audit trail `PSY.audit`) — read the data first. Live events (things the user does now: approving an appeal, a voice call they start) are added on top; existing `PSY.audit` entries for the case appear too, tagged by who did them.
- `PSY.hist.list(caseId, { scope })` → events newest first. `PSY.hist.add(ev)` (through `POST /cases/:case/history`).
- `PSY.hist.html(caseId, { scope, title='History', open=false })` → a **dropdown (collapsible) History** block: header "History · N events" with chevron; inside: small filter chips by actor (All · Voice agent · Psyflo agent · Psyflo AI · Staff · From Lauris · Payer, counts), then rows: date and time on the left, the action (bold) and a one-line detail, a "View" link when the event has a pop-up, the actor tag on the right. Compact; no paragraphs.
- Pop-ups (`PSY.ui.modal`): **call** → the voice-call pop-up (below); **doc/letter/submission/note/analysis** → a pop-up with the facts (document name, date, author, what it contains or what was submitted, confirmation/reference number, a link "Open in Lauris" or "Open in Denial Intelligence" where one exists). Every row that has more to see opens a pop-up.
### `PSY.voice` — the voice agent (`src/screens/09-voice.js`, HIST13)
- `PSY.voice.start(caseId, { purpose: 'sra-status'|'denial-followup'|'reference'|'p2p', scope })` → `POST /voice-calls` → a live call pop-up with steps and an ETA: Dialing the payer's provider line → Phone menu → On hold → Speaking with a representative → Summary. "Simulated" chip, "Sped up for the demo". On finish: a History event (`actor.kind 'voice'`, `pop.kind 'call'`), a toast, and the pop-up switches to the result.
- `PSY.voice.button(caseId, { purpose, scope, label })` → html of a button (default label "Call payer · voice agent").
- Call pop-up (also opened from History): header (payer plan name, purpose, date and time, duration, outcome, **reference number** — fictional, marked Simulated); tabs **Summary** (3–6 bullets: what was asked, what the payer said, reference number, next step) and **Transcript** (the full turn-by-turn conversation, Voice agent / Representative labels, timestamps); buttons "Copy summary" and "Add note to History". Scripts are written per case and purpose from the case's own facts (status, decision, letter reasons, units). The voice agent identifies itself as an automated assistant calling on behalf of Harvest; no PHI beyond initials and the reference numbers the demo already shows; never a Medicaid ID; the representative never states a rule, deadline or rate that the demo doesn't already cite (they can confirm "the deadline in the letter").
