## Decisions (they reconcile the prompt with the user's earlier, explicit requests — follow them)
1. **Wording: "consumer", not "patient".** The user asked in Round 7 to use Lauris's own vocabulary (Lauris says Consumers). Wherever the prompt says patient, the UI says consumer ("Consumer", "Consumer ID"). Keep "Lauris #" for the identifier.
2. **Summary metrics are a compact, clickable count strip, not big white tiles.** The user asked in Round 6 to replace "big white boxes at the top" with filters. So each metric the prompt lists is a small count chip in one row (e.g. `Active 4 · Pending reviews 2 · Expiring soon 2 · Partially approved 3 · Denied 1 · Renewals due 2`) and clicking a chip applies that filter. The dropdown filter bar (`PSY.fb`) stays under it. Same pattern for Denial Intelligence's dashboard metrics. "Denial trends by payer" is a small inline bar row, not a chart box.
3. **Copy stays lean (Round 7).** Labels, data and one short line where the prompt asks for a reason ("Why it matters" is one sentence). No paragraphs, no instructions that restate the UI. Toasts ≤ 6 words.
4. **Roles and caseloads (foundation, done):** DSS = Kayla Hale (direct care, Campbell ES-1; assigned M.R. 4471 and T.N. 4441). LCS = Jordan Perez, LPC (9 consumers). A second clinician, Sam Ortiz, LCSW, has L.V. 4426 and P.G. 4419. Admin = Maria Wood, Program Director (all 11). Defaults: DSS Scribe (DPN, Collateral, Monthly) + Track Time; LCS Scribe (all 5) + Track Time + Scan & Enhance + Case status + Authorizations + Denial Intelligence (own caseload) + clinical record content; Admin Authorizations + Denial Intelligence + Analytics + Settings + all consumers + case status, **no clinical record content, no Scribe/Scan & Enhance by default** ("do not assume administrative privileges authorize access to all sensitive clinical records"). Where an admin would see clinical text (DI evidence review, note excerpts), show the item's name/date and "Restricted · clinical access" instead of its content, unless `PSY.can('clinicalRecords')`. Admin can change any of this in Settings → Roles.
5. **Simulated vs real.** Every simulated step carries a Simulated chip (`PSY.ev.label('illustrative','Simulated')`): payer submission, agent sign-ins, report generation from "Lauris", sync to Lauris is the demo's own simulated Lauris (say "Synced to Lauris" — the demo Lauris is the target). Demo data panels carry "Illustrative demo data".
6. **Downloads are real now.** The artifact will declare the `downloads` capability. Use `PSY.download(filename, data)` with `PSY.csv(rows)` or `PSY.pdf(title, lines)` (foundation). In a local file it falls back to a preview modal; tests must accept that.
7. **Never fabricate.** Recommendations cite record evidence (document + date, `PSY.ev.cite`), or say "Not documented · collect it". Psyflo never signs. Appeals/P2P statements are traceable to documents.
